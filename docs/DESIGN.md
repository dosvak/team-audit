# Team Audit (PTAUD) - process application

Every team of every installed application with its members, flagged when empty or held by a single user; the items exposed to the technical user (what can be started / opened); a user lookup that resolves groups and team memberships.

Package `Team-Audit-1.0.twx` (generated by `tools/build_ptaud.py` on twxkit + kitlib, standard library only, no base export); targets: 8.6.2, BAW 24-26 (classic v1 API).
Vanilla BAW: UI Toolkit controls only, one client-side human service, server-side service flows calling the REST API with the technical
user of the environment variables. Import through the Process Center / Workflow Center console (`pc_import.py`) or Studio, set the
environment variables of the snapshot, open the dashboard from Process Portal or the playback URL of the `.ids.json`.

## Dashboard

| Tab | Content |
|---|---|
| Teams | application filter, Audit teams, Export CSV; table team / application / snapshot / type / users / groups / members / flag |
| Exposed items | List exposed items; table type / item / application / snapshot / tip |
| User lookup | login -> groups and teams |

Every list has a status line; errors open a message modal; CSV export shows the text in a modal for copy / paste.

## Service flows and REST calls

| Flow | Does |
|---|---|
| PA Init | header |
| PA Audit Teams | `GET /processApps` (installed snapshots per application) + `GET /globalTeams` (teamId, teamName, processAppName) + `GET /team/{teamId}?snapshotId=<2064.x>` per team (tries the active snapshot first, then the newest) -> members, type, flags EMPTY / single member / by service |
| PA Exposed Items | `GET /exposed` -> type, name, application, snapshot, tip |
| PA User Lookup | `GET /user/{login}?includeInternalMemberships=true` -> plain groups + team memberships parsed from `<Team>_T_<team uuid>.<snapshot uuid>` (T = members, S = managers) |
| PA Rows To CSV | team rows -> CSV |

## Environment variables

`serverBaseURL`, `restAuthUser`, `restAuthPassword`, `restTrustAllCertificates` (kit-rest.js: the technical user every server-side flow calls the REST API with), `appTitle`.

## Business objects

PAQuery, PATeam, PAResult, PAItem, PAItems, PAUserQuery, PAUserRow, PAUserResult, PACsv.

## Build, test, verify

```
python3 tools/build_ptaud.py --snapshot 1.0                       # -> Team-Audit-1.0.twx + .ids.json
KITENV_serverBaseURL=https://<host>:9443 KITENV_restAuthUser=<user> KITENV_restAuthPassword=<pw> \
  python3 tools/build_ptaud.py --snapshot 1.0-lab                 # lab build with real defaults (a snapshot caches tw.env: new name)
python3 tools/pc_import.py Team-Audit-1.0-lab.twx
python3 tools/kit_flow_test.py Team-Audit-1.0-lab.ids.json "<flow>" '{"data": {...}}'   # every flow over REST
python3 tools/dash_test.py <host> <branch> <cshs>             # playback: tabs, JS errors, failed calls
```

Verified: 8.6.2.20001 lab: 63 teams of all installed applications (1 empty, 25 single-member), the 6 teams of HDLS with members, 68 exposed items, membership lookup of deadmin (8 groups, 26 team memberships), unknown user reported (CWTBG0007E). Dashboard playback: no JavaScript error, no failed call.

## Pitfalls met

* `GET /team/{id}` needs `snapshotId` (CWTBG0011E); `/globalTeams` gives no snapshot, so the app tries the snapshots of the owning application.
* `GET /exposed` carries no team: which team an item is exposed to is not readable over v1 on 8.6.2 (on BAW 24+ `/ops/std/bpm/installedApps/teams?filter=&snapshotId=` exists).
* `GET /search/meta/{type}` rejects `task` / `instance` on 8.6.2 - the column list is documented, not discoverable.
