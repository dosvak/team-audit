# Team Audit (PTAUD)

Every team of every installed application with its members, flagged when empty or held by a single user; the items exposed to the technical user (what can be started / opened); a user lookup that resolves groups and team memberships.

**Target:** IBM BPM 8.6.2, IBM BAW 20-26 (traditional) and CP4BA (Workflow Authoring / Studio import). Built from out-of-the-box building blocks only (System Data, UI Toolkit, one client-side human service,
server-side service flows calling the product REST API as a technical user) - no third-party toolkit, no custom Java.

## Install

1. Import the package of your platform:
   * IBM BPM 8.6.2 / IBM BAW 20-26 traditional: `packages/Team-Audit-1.0.twx` (Process Center / Workflow Center console: *Import Process App*);
   * CP4BA (Business Automation Studio > *Import*): `packages/Team-Audit-1.0-CP4BA.twx` - the same app bound to the Cloud Pak System Data
     (`8.6.0.0_TC`) with `serverBaseURL` defaulting to the Studio loopback `https://localhost:9443/bas` (on a Process Server set it to
     `https://localhost:9443/baw-<instance>`). After the import create one snapshot in the Studio and install / play back that one: an
     imported generated snapshot carries no compiled theme and renders unstyled outside the branch tip. This build also imports on
     traditional BAW 20.0.0.1 and later.
2. Set the environment variables of the snapshot (below): the server base URL as seen from the server itself and the technical user the
   flows call the REST API with. The package ships no password.
3. Expose the dashboard to a team (the package's default team holds `celladmin`; change it) and open it from Process Portal or the
   playback URL of the human service.

## Dashboard

| Tab | Content |
|---|---|
| Teams | application filter, Audit teams, Export CSV; table team / application / snapshot / type / users / groups / members / flag |
| Exposed items | List exposed items; table type / item / application / snapshot / tip |
| User lookup | login -> groups and teams |

## Environment variables

`serverBaseURL`, `restAuthUser`, `restAuthPassword`, `restTrustAllCertificates` (kit-rest.js: the technical user every server-side flow calls the REST API with), `appTitle`.

## Rebuilding and customising

The application is generated by a small Python program on the twxkit generator (standard library only, no base export). The generator
and the kit are served to AI agents and developers by the **BAW Knowledge MCP server** (`https://bawmcp.dosvak.com/mcp`, see
[dosvak/baw-mcp](https://github.com/dosvak/baw-mcp)): `get_package('team audit (ptaud)')` returns this package, `get_tool('build_ptaud.py')`
the generator - ask the MCP for the kit apps and it hands out the generator by name.
